# API существующего приложения

Ответ: `{"data": ...}`; ошибка: `{"error": "описание"}` с соответствующим
HTTP-статусом. JSON UTF-8. Заголовок `X-Demo-User: 1` выбирает Анну,
`2` — Бориса, `3` — Веру. По умолчанию 1. Это открытый демо-переключатель,
не доказательство личности; локальный API не предназначен для публикации в сеть.

| Метод и путь | Текущее поведение |
|---|---|
| `GET /api/health` | Проверка запуска сервиса |
| `GET /api/context` | Демо-пользователи, выбранный пользователь, время UTC и дата создания демо |
| `GET /api/projects` | Только проекты текущего пользователя, участники и количество задач |
| `GET /api/projects/{id}/tasks` | Все задачи доступного проекта |
| `GET /api/attention` | Список «Требует внимания / Утренний фокус»: задачи с сигналами внимания (см. ниже) |
| `POST /api/projects/{id}/tasks` | Создать задачу в активном проекте |
| `GET /api/tasks/{id}` | Доступная задача с комментариями и авторами |
| `PATCH /api/tasks/{id}` | Изменить поля с проверкой версии |
| `POST /api/tasks/{id}/comments` | Создать комментарий в доступной задаче; возвращает 201 с объектом комментария |

Поля задачи для создания и изменения: `title`, `description`, `status`,
`assignee_id`, `due_at`. При создании `title` обязателен. Неизвестные поля
отклоняются. Исполнитель — участник проекта или `null`. Даты — строго
`YYYY-MM-DDTHH:mm:ssZ` либо `null`; текущий UI редактирует их с точностью до минуты.
Для PATCH обязательно целое поле `version`, полученное при чтении.
Успешное изменение увеличивает версию; устаревшая версия возвращает 409.
Метод добавления комментария принимает `{"body":"текст"}`. Проверяется доступ
к задаче, архивность проекта и длина `body` (до 5000 байт). Успешный ответ —
HTTP 201 с объектом комментария: `id`, `task_id`, `user_id` (автор комментария),
`body`, `created_at`, `author` (имя пользователя с ролью). При добавлении
комментария версия задачи не изменяется (запросов к таблице `tasks` нет).
Чтение существующих комментариев доступно через карточку задачи.

Максимумы строк в байтах UTF-8: название 200, описание 10000, комментарий 5000.
Максимум тела изменения — 32 KiB. Ошибка валидации — 422, JSON — 400,
неизвестный пользователь — 401, отсутствующий или недоступный объект — 404,
запись в архив — 409. Поиск и фильтр статуса в текущем UI выполняются локально.

## `GET /api/attention`

«Требует внимания / Утренний фокус» — список незавершённых задач текущего
демо-пользователя, по которым накопились сигналы внимания.

Доступ: задачи активных проектов текущего демо-пользователя (`p.archived = 0`
и участие в `project_members`); чужие проекты недоступны. Невыполненные задачи
(`status != 'done'`) выбираются с полями: `t.*`, `project_name`,
`assignee_name` (LEFT JOIN, может быть `null`). Для каждой задачи
включается `last_comment` (`body`, `created_at`, `user_id`, `author`;
`null` без комментариев) — последний комментарий сортировкой `id DESC LIMIT 1`.

Сигналы (массив `reasons` с объектами `{code, label, severity}`):

| code | severity | label | Условие |
|---|---|---|---|
| `overdue` | high | `Просрочена` | `due_at` задано и меньше текущего времени в UTC |
| `blocked` | high | `Заблокирована` | `status = 'blocked'` |
| `blocker_in_comment` | high | `Препятствие в обсуждении` | в последнем комментарии есть сигналы «нужна помощь», «помощь руководителя», «без доступа», «нет доступа», «ждёт решения», «блокер», «проблема», «застряли», «не могу» и нет отрицаний «препятствий нет», «расхождений пока нет», «проблем нет» |
| `waiting_reply` | medium | `Ждёт ответа` | комментарии есть и последний комментарий оставлен другим пользователем (`last_comment.user_id !=` текущий) |
| `unassigned` | medium | `Без исполнителя` | `assignee_id` не задан |

Задачи без причин внимания не возвращаются. Сортировка: больше high-причин
первым, затем `due_at` по возрастанию (без срока — позже), затем `id`.
`score` = 3 на каждую high-причину + 1 на каждую medium-причину.

Пример ответа (фрагмент):

```json
{
  "data": [
    {
      "id": 7,
      "project_id": 2,
      "project_name": "Автоматизация отчётности",
      "title": "Определить владельца справочника",
      "status": "open",
      "assignee_id": null,
      "assignee_name": null,
      "due_at": null,
      "last_comment": { "user_id": 2, "author": "Борис · разработчик", "body": "Не можем продолжить без владельца справочника…", "created_at": "2026-11-22T10:00:00Z" },
      "reasons": [
        { "code": "waiting_reply", "label": "Ждёт ответа", "severity": "medium" },
        { "code": "unassigned", "label": "Без исполнителя", "severity": "medium" }
      ],
      "score": 2
    }
  ]
}
```

Ошибки: 401 — неизвестный демо-пользователь.
